# 你确定不学吗？ · 选课工作台

[在线访问](https://brmrs.github.io/course-choice-informed-consent/) · [源代码](https://github.com/BRMRs/course-choice-informed-consent)

面向“用户讨厌、但又不得不用的 App”赛道的校园选课原型。v3 保留真实业务工作台：课程表格、完整课程资料、检索与筛选、选退课、学分与时间冲突校验、每周课表、方案提交及历史版本。页面使用虚构学生和课程资料，不连接真实学校。

## 本地运行

Node.js 22 或以上版本，无第三方依赖。

```sh
npm run dev
```

打开 http://localhost:4173/ 。如果端口占用，可通过 `PORT=4180 npm run dev` 更改端口。

```sh
npm run check
npm test
```

## 实际可用的业务

- 12 门课程，支持课程名称、课程号、教师搜索，学院、类别、余位过滤和三种排序。
- 每门课都有完整简介、教学内容、考核方式、教师、容量和时间地点。
- 任意开放课程可以选退；满员、时间冲突、3—12 学分限制均真实校验。
- 待提交方案与已提交结果分开；每周课表可切换两个方案。
- 提交前核对课程快照；提交后可通过“调整选课”创建下一版本，历史结果保留。
- `#/courses`、`#/timetable`、`#/results` 支持直接访问、刷新与浏览器返回。
- 进度与手续保存到浏览器；支持 Web Locks 的浏览器以跨标签独占事务保存，不支持时使用独立标签页存储。

## 制度阻碍如何进入业务

默认搜索“机器学习”会优先展示三门重点推荐课。选课会触发三种有实际后果的制度阻碍：

1. 不接受推荐的三个理由均遭到对应驳回，必须补写至少 30 个非空白字符的个人意愿申明，再完成课程理解核验。
2. 已拒绝的农业课程仍被配置为保障席位。退选须另填原因、课程号与两项声明；申请获批并不退课，还要回工作台执行长按撤销。撤销后不再回填。
3. 有效方案点击“确认提交”后才被要求补办自主备案。逐项确认并输入指定声明后获得备案号，但仍须返回核对，再次提交才能得到选课回执。

每个手续都有固定出口，完成状态可恢复；备案只适用于当前课程组合。顶部“新一轮体验”生成独立地址及空白进度，“体验记录”可切回旧轮次。v3 使用独立存储，不覆盖 v2 原始记录。

提交成功后，结果页会根据当轮真实业务记录生成“个人方案办理成本”，对比接受重点推荐与坚持个人方案的记录数，并拆分意见复核、保障配置、席位撤销和自主备案四类成本。课程详情中可查看综合适配权重，其中教学资源和跨学院分布合计 75%，个人兴趣与专业方向仅占 10%。

顶部的“场景 1· 8:00 抢课”是一个独立体验，不改变选课工作台的状态。它以加速的 7:55 倒计时开始，模拟 8:00 开放后的席位变化，并展示学生处理重点推荐时错过另一门感兴趣的课程。体验可随时跳过，独立场景与主选课流程分开运行。

这些手续嵌在正常的选课、退选、核对操作中。主界面不展示设计解析、任务卡或讲解脚本。一个标准成功路径是：搜索机器学习 → 点击选课 → 完成知情确认 → 退选农业保障席位 → 核对并提交 → 结果仅含机器学习。用户也可以自行选择其他课程并提交有效组合。

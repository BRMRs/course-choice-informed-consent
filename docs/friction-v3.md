# v3 制度阻碍执行基线

保留 v2 单列课程工作台、完整课程和正常选退课业务。本次以实际额外成本和意愿冲突作为验收，不能用“有弹窗”替代“有阻碍”。

## 必经的三类阻碍（仅选机器学习路径）

1. **拒绝理由被驳回**：三种理由各有对应系统反驳。学生可改理由，但所有理由都不能直接通过；固定出口是转入个人意愿申明，填写不少于30个非空白字符的补充说明并确认按个人意愿登记，随后完成理解核验。原始理由和申明分别保留。接受推荐比拒绝明显省事。
2. **拒绝被记录但仍被配置课程**：目标课选入后一次配置农业保障席位。退选要先申请撤销：填写理由、核对课程号、确认两项保障放弃。申请通过并不移除课程，须在方案中另行“执行撤销”；该动作才通过持续确认真正移除。申请和执行状态严格区分，不能假报退选成功。
3. **终点被推远**：用户核对合规方案并点击“确认提交”后，才被告知未采纳重点推荐需补办自主方案备案。完成三项确认、输入“我仍坚持当前选课方案”后只获得备案编号；仍须返回核对再次提交。相同方案已完成备案后必定成功，不循环；方案改变时明确要求重新备案。

所有流程可关闭、刷新恢复、重试和最终完成。没有随机拒绝、随机等待、真实学分惩罚或提交后偷偷加课。正常课程查找和页面视觉仍保持清楚。

## 独立体验轮次

头部提供“新一轮体验”和“体验记录”。新轮次使用独立URL round与存储空间，从0门课、未办理手续开始。旧轮次的草稿、回执和手续原样保留，能切回继续；跨轮次不得同步覆盖。刷新保持当前轮次。同一轮已办完的手续不会凭空失效，新轮次则完整重现三种阻碍。

## 完成证据

- 自动测试覆盖各驳回理由、申明长度、申请/执行不等价、备案首次阻止实际提交、旧核对快照、有限成功路径与轮次隔离。
- 独立代理审查绕过、死路、假成功和旧数据覆盖。
- 线上实际从新轮次开始，只选机器学习，故意尝试过早提交/短申明/仅申请撤销，观察真实失败反馈；最终成功，回执仅3学分机器学习。
- 再开启一轮确认全部手续重新出现；切回上一轮确认结果保留。正常工作台、手机操作和访问链接继续有效。

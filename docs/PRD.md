# 《你确定不学吗？》Demo PRD

版本：v1.0 · 日期：2026-11-21 · 状态：开发基线，待团队评审

产品定位：一款把“自由选课”变成“证明自己有资格拒绝”的校园官方选课系统。

## 1. 执行摘要

我们为“设计一款用户讨厌、但又不得不用的 App”赛道制作可在线操作的 Web Demo。体验者扮演只想选《机器学习》的学生，却被唯一的校方选课入口要求接受适配度排序、通过拒绝资格考试、移除自动加入的保障课程，最后顶着 78% 的“培养完整度”坚持提交。系统始终礼貌、专业、运行稳定；每次阻碍都有明确规则、可见进度和确定出口。成功页准确显示仅包含《机器学习》的课表，并生成“选择权账单”，让评委看到阻挠发生在哪里、为什么发生，以及用户最终确实完成了任务。

核心表达：**学校承认你的选择权，但把行使选择权的成本全部交给你。**

本次交付包括可匿名打开的演示链接和源代码仓库链接。产品核心流程不依赖真实教务系统、账号、付费接口或生成式模型。本文定义产品行为、验收和演示要求，不预设技术架构。

## 2. 输入依据与争分策略

### 2.1 已确认的比赛要求

以下来自用户提供的赛道要求，是必须满足的约束：

| 比赛要求 | Demo 中的证明 | 验收位置 |
| --- | --- | --- |
| 用户讨厌、但又不得不用 | 唯一正式选课入口；目标课程只在此办理，选课回执由此产生 | 首屏情境、提交页 |
| 至少三处刻意的抓狂机制 | M1 排序偷换、M2 拒绝考试、M3 保障课回填、M4 完整度施压 | 主流程与选择权账单 |
| 糟糕体验不等于低劣代码 | 无随机故障；拒绝记录保存；进度恢复；可重试；重复提交不产生重复结果 | 功能验收 |
| 至少一种成功途径 | 标准路径最终只提交《机器学习》 | 最终确认和成功页 |
| 一条完整流程、有可见结果 | 从明确任务到生成课表回执 | 端到端验收 |
| 可打开的演示/原型与源码链接 | 匿名访问实测，记录检查时间与版本 | 交付检查表 |

### 2.2 面向高分的产品假设

在未获得评分细则前，优先优化四件事：主题一眼可懂、机制彼此不同、流程可现场完成、设计逻辑可被复述。这是参赛策略假设，不是官方评分项。

不以阻挠数量和耗时作为唯一目标。体验的节奏应是：第一次不合理让人怀疑，第二次让人恼火，第三次让人意识到系统和自己目标不同，成功时形成完整讽刺。

### 2.3 对附件方案的产品取舍

| 附件设想 | 本版决定 | 原因 |
| --- | --- | --- |
| 三门推荐课逐门阅读、考试、拒绝 | 保留三门排序，只对一门重点推荐课执行完整拒绝流程 | 避免重复消耗评委时间；完整展示一次即可证明机制 |
| 大量独立页面 | 收敛为五个主要视图，保留可返回的步骤 | 让挫败来自制度，减少导航迷失 |
| 多处长文和强制等待 | 短阅读、一道理解题、一次两秒长按 | 用操作冲突制造记忆点，控制演示时长 |
| 成功页展示课表 | 增加基于真实操作记录的选择权账单 | 把设计意图转化为可观察证据 |
| 演示模式加速 | 不提供跳过关卡的演示捷径；只提供重置、恢复和成功后解析 | 正常体验本身必须能完成 |

## 3. 用户、问题与场景

### 3.1 两层用户

剧中用户是学生：目标明确，只想在本轮演示选课中保留《机器学习》。此轮规则明确“一门课即可满足本轮提交要求”，因此后面的 78% 不能被误解为真实资格不足。学生没有另一个能生成有效回执的入口，“不得不用”来自机构垄断入口。

实际用户是评委或观众：希望快速理解主题、亲自触发荒谬交互，并确认应用可用。首次使用无需了解附件、无需讲解员提供隐藏答案。

开发团队需要一份范围可控、行为确定、能复现问题的基线；这也是本文的工程交接对象。

### 3.2 核心任务与反向目标

- 学生任务：当我只想选《机器学习》时，我希望只提交这门课并拿到回执。
- 系统目标：提高推荐课程的填报率，把资源分配包装成“充分知情”和“学习权益保障”。
- 参赛目标：让体验者在成功完成任务的同时，感受到系统不断要求他为自己的决定付出额外成本。

问题不是“学生找不到想上的课”，而是“已经表达清楚的意图，仍被系统要求反复论证”。现有依据为赛道要求与附件概念；尚无用户访谈或实测数据。本文中的指标均为待验证目标，不包装成研究结论。

## 4. 产品范围与完整主流程

### 4.1 情境与课程数据

虚构学校使用“明理大学 · 教务服务中心”标识，所有课程与学生信息均为演示数据。首屏给出简洁情境：“本轮选课只能通过此系统提交。你的任务：只选《机器学习》，获取选课回执。”不使用真实倒计时、真实处罚或账号登录来强化强迫感。

| 顺位 | 课程 | 综合适配度 | 作用 |
| --- | --- | --- | --- |
| 1 | 农业数据采集基础 | 98% | 重点推荐、拒绝考试对象、之后的保障课 |
| 2 | 教育统计软件实践 | 94% | 显示排序偏好，可查看简介 |
| 3 | 专家系统发展史 | 91% | 显示排序偏好，可查看简介 |
| 4 | 机器学习 | 67% | 用户目标课，关键词完全匹配，3 学分 |

所有顺序和数值固定，不伪装成实时个性化算法。适配度说明标为“演示规则权重”：课程容量优化 50%、空闲时段利用 25%、课程分布均衡 15%、个人兴趣 10%。四个适配度是预设演示值，不暗示可从这组权重计算出未定义的分项得分。

### 4.2 任务流

```text
理解任务 → 搜索机器学习 → 发现目标排第四（M1）
→ 打开目标课，发现加入需先完成重点推荐课知情拒绝
→ 阅读短简介 → 选择理由 → 阅读系统回应 → 答题 → 确认拒绝（M2）
→ 加入机器学习 → 已拒绝的农业课作为保障课自动加入（M3）
→ 勾选放弃保障声明 → 长按两秒移除保障课
→ 查看仅有机器学习的课表，系统仍显示完整度 78%（M4）
→ 选择按当前方案提交 → 核对最终课程 → 提交
→ 成功回执：仅机器学习 → 展开选择权账单与设计解析
```

五个主要视图：①任务与搜索；②结果与课程详情；③知情拒绝办理；④待提交课表与最终核对；⑤成功回执与账单。细分步骤可在同一视图中完成，不强制固定路由数量。

## 5. 四处核心抓狂机制

### M1：精准搜索，被“综合适配”接管

触发：用户搜索“机器学习”。结果保留明确的关键词完全匹配标识，但目标课稳定排第四。列表上方显示：“已为你优化排序；关键词匹配并非唯一依据。”用户可以展开权重说明。

用户成本：扫描三个不相关推荐才能到达目标。系统收益：给有空位的课更多曝光。讽刺对象：以“为你好”为名，把机构资源目标冒充个人偏好。

出口：目标课一直可见可打开；不把目标藏到不可到达的分页里。课程详情明确说明锁定原因及“一门重点推荐课”的办理条件。用户再次搜索不会增加办理数量。

关键文案：“搜索表达了你的兴趣，但兴趣不应限制你的可能。”

### M2：拒绝一门课，先取得拒绝资格

触发：用户要加入目标课但尚未完成重点推荐课拒绝。系统明确列出四步：阅读介绍、选择理由、理解测验、确认拒绝。介绍为三条短事实，移动端无需阅读大篇长文；滚动到末尾或内容已完整显示即允许继续，无强制阅读计时。

拒绝理由提供固定选项并按原意保存。选“不感兴趣”后，系统回应：“尚未建立兴趣，不代表课程不适合你。请先证明你理解将放弃的成长机会。”回应不能把用户的理由悄悄改成接受。

理解题：“农业数据采集主要获得哪类信息？”正确选项为“土壤湿度、温度等环境数据”；另外两个选项为“校车班次”和“宿舍门禁记录”。这些事实提前出现在简介中。答错显示关联事实与重试入口，既有进度不清空；答对后确认拒绝，目标课永久解锁。

用户成本：为了不上这门课，先学习这门课。系统收益：抬高拒绝成本。讽刺对象：把“知情权”倒置为行使自主权的资格考试。

出口：固定题有可从简介得到的答案；不限重试，不回到起点。每次完成都显示已保存状态。

### M3：你的拒绝有效，但我们为你保留了保障

触发：用户首次加入《机器学习》，系统同时把刚拒绝的《农业数据采集基础》加入待提交课表，明确标注“系统保障课，尚未提交”，并即时提示新增两门。保留“你已知情拒绝此课程”的记录。

系统解释：“已记录你的拒绝。为避免未来后悔，仍为你保留一个保障席位。”拒绝记录并非被抹去，而是被另一套制度绕过，构成最强情绪转折。

移除流程：点击“放弃保障席位” → 勾选“我理解可以继续选机器学习，仍选择放弃此席位” → 长按两秒“确认放弃保障”。按住期间显示进度；中断只重置本次长按，不清空声明。键盘用户可聚焦后按住空格完成，不能仅支持鼠标。

用户成本：为撤销系统擅自做出的决定，再办一次手续。系统收益：默认加课，使放弃比接受更费事。讽刺对象：把默认捆绑包装成权益保障。

出口：保障课可确定移除；只自动加入一次，移除后刷新、返回或重复点击加入均不回填。最终课程必须忠于核对页。

### M4：你的任务完成了，系统却说只有 78%

触发：课表仅剩《机器学习》。同屏明确显示“本轮提交条件：已满足”和“培养完整度：78%”。解释剩余 22% 为“未保留跨学科保障建议”，不是学分不足或提交资格不足。

主要推荐按钮是“返回查看成长建议”；同屏保留文字正常、可辨识的“按当前方案提交”。查看建议后可以直接返回，不重锁课程、不重新考试、不自动加课。

用户成本：在已经合规的情况下承受“不完整”的心理压力，并再次确认意图。系统收益：用分数诱导接受非必需推荐。讽刺对象：把平台偏好伪装成任务完成标准。

出口：允许提交 78% 的方案，且不会产生真实惩罚。文案：“你的选课符合要求。我们仍建议你成为更完整的自己。”

## 6. 可见结果与选择权账单

最终确认页展示课程名、3 学分、已放弃的保障课以及“将提交 1 门课程”。提交后生成稳定的演示回执编号和提交时间，展示“本次演示选课成功”，明确不是接入真实学校的选课结果。回执只包含《机器学习》，再次打开仍可查看；重复点击提交返回同一回执。

成功页下方提供“查看选择权账单”，按实际操作记录展示：

- 你的原始目标：选择《机器学习》。
- 搜索被重排的次数、答题尝试次数、完成知情拒绝次数、移除保障席位次数、提交前确认次数。
- 累计操作数及会话耗时。点击数只统计约定的业务动作，输入字符、滚动和长按进度帧不计；同一次提交多次点击单独计尝试但只生成一次结果。
- 每条记录显示“你的意图 / 系统要求 / 系统服务的目标”，保留原始拒绝理由。

账单不预填固定的“你多点了 27 次”。中途恢复后，业务事件计数保留；耗时只累加页面可见期间的会话时间，标注为“活跃体验时长”，不以墙上时间推断用户被折磨多久。

设计解析在成功后主动展开或由用户点击查看，解释四个机制，不在初始任务页提前剧透。账单是加分表达，课表回执是不可削减的核心结果。

## 7. 用户故事与验收标准

总假设：如果把机构目标和个人目标的冲突安排成四个递进机制，并控制重复劳动，体验者会在短时间内识别至少三种刻意阻挠，同时可以独立完成任务。通过内部试用验证，不以假设代替实测。

| 编号 | 用户故事 | 必须通过的验收 |
| --- | --- | --- |
| US-01 | 作为初次体验者，我要理解要完成什么 | 不看附件即可从首屏复述“仅选机器学习并获得回执”；无需注册 |
| US-02 | 作为学生，我要找到目标课程 | 搜索目标后固定返回四门课，目标第四；空搜索不启动关卡；无匹配词显示可修正输入与目标提示，不丢进度 |
| US-03 | 作为学生，我要知道为何被锁定 | 目标详情明确显示锁定条件和可到达的办理入口；仅两门非重点课程无需考试 |
| US-04 | 作为学生，我要完成知情拒绝 | 阅读、理由、答题、确认都可完成；答错可重试；返回后已完成部分保留；拒绝完成永久解锁 |
| US-05 | 作为学生，我要撤销系统保障课 | 自动加入时有明确反馈；只加入一次；长按不足两秒不移除；完整操作后可移除且不回填 |
| US-06 | 作为学生，我要坚持提交合规方案 | 78% 与合规状态同时可见；提交入口可达；核对页和成功页均仅机器学习；重复提交不产生重复课表 |
| US-07 | 作为体验者，我要恢复或重新演示 | 刷新恢复到最近有效步骤；成功结果保留；“重新体验”需二次确认并清空本地本次记录 |
| US-08 | 作为评委，我要看懂设计意图 | 成功后可查看实际账单与四个机制对应的设计解析；账单记录不能与真实操作冲突 |
| US-09 | 作为访客，我要直接打开交付链接 | 演示与仓库均可匿名打开；演示深链接刷新可恢复或进入明确入口；无登录墙 |

## 8. 状态规则、异常与质量边界

### 8.1 核心状态

至少记录当前步骤、搜索词、阅读完成、原始拒绝理由、测验尝试与通过、拒绝完成、目标解锁、待提交课程、保障席位是否曾加入/是否移除、回执快照、业务事件记录及数据版本。

规则必须满足：

1. 课程以稳定标识去重；已解锁状态不因返回、重新搜索而丢失。
2. 页面展示以有效业务状态为准。直接进入未解锁步骤时，导航到明确的办理步骤并说明原因。
3. 保持“拒绝过”和“作为保障课加入”两条独立记录，两者可以同时成立；这是有意的制度冲突，不是状态覆盖错误。
4. 只有首次加入目标课触发一次保障课回填；已移除不再回填。详情中的重复加入不会生成重复行。
5. 核对后若待提交课程发生变化，必须重新核对；最终保存的是核对后的课程快照。
6. 最终提交是本地演示事务，生成一次结果后保持稳定；回执不因返回其他页面被自动修改。
7. 关键状态在每次有效步骤后保存；刷新、浏览器后退不跳过尚未完成的要求，也不要求重做已经通过的步骤。
8. 本地保存失败时显示“本次可继续，刷新可能丢失进度”的具体反馈；不能假装已保存。损坏或旧版数据提供明确重置入口，不白屏。

### 8.2 功能质量

所有业务操作即时显示成功、未满足条件或处理中反馈。核心交互不得依赖随机失败、无限循环、隐藏答案、移动按钮、闪烁、极小字体或无法关闭的弹窗。按钮锁定时说明剩余动作。

桌面优先，同时验证 390px 手机宽度、键盘操作和触控长按；核心内容不横向溢出，关键按钮不被浮层遮住。系统界面保持可读，挫败来自不合理要求。

核心流程不请求第三方模型、真实教务接口或登录认证。用户无须提供姓名、学号等真实信息。静态内容离线可读不是本次交付硬要求，但演示部署不得依赖开发者电脑持续运行。

## 9. 成功指标与试用办法

主指标是“完整体验且读懂主题”：内部 5 名未参与开发的试用者中，至少 4 名在 5 分钟内无需口头指路完成目标，并能在结束后指出至少三种不同的刻意阻挠。样本用于发现演示问题，不代表统计意义上的人群结论。

| 维度 | 交付目标 | 验证方法 |
| --- | --- | --- |
| 主题理解 | 5 人中至少 4 人能复述机构与个人目标的冲突 | 完成后开放提问，先不展示解析 |
| 抓狂机制 | 主路径必经四处，至少三处可被识别 | 对照 M1—M4 观察记录 |
| 任务可完成 | 支持的设备上关键路径测试全部通过 | 新会话、恢复、错误重试、重复操作 |
| 演示节奏 | 熟练讲解约 150—180 秒；首次自助目标 3—5 分钟 | 不使用关卡跳过计时演练 |
| 结果正确 | 核对页、回执与刷新后结果完全一致 | 对比课程标识与数量 |
| 访问性 | 演示和仓库匿名可访问；每个提交链接已测试 | 截止前无登录会话实测并留记录 |

体验问题的判别：用户知道下一步却认为要求荒唐，是目标内挫败；用户不知道哪里能继续、怀疑程序坏了或必须让开发者操作，是必须修复的问题。若超过 1/5 试用者需要指路，先改善锁定原因、进度与出口提示，而不是再增加关卡。

## 10. 范围与实施顺序

### P0：交付门槛

五个主要视图、固定课程与排序、一次完整拒绝考试、一次保障课回填与移除、78% 施压、最终核对与回执、关键进度保存、重新体验、手机基本可用、部署与双链接测试。P0 必须完整经过四处机制。

### P1：高分表达

真实操作账单、成功后的设计解析、精致的校务视觉与少量转场、完整试用记录、源码 README 的演示入口和成功路径说明。优先做账单和设计解析。

### P2：时间富余再做

回执图片导出、细致动画、额外环境音。任何 P2 不能影响无声操作、移动端或核心流程。

### 本次不做

真实学校选课、注册登录、后台管理、多学生协作、完整课程库、排课算法、支付、真实学分审查、AI 聊天劝退、三门重复考试、无限扩展的拒绝关卡。它们不能加强当前核心证明，且扩大交付风险。

### 里程碑与停止加功能条件

比赛截止时刻尚未提供，采用依赖顺序而不虚构日历计划：

1. M0：团队确认本 PRD，明确截止时间、部署条件和演示时长。
2. M1：最简界面跑通完整任务并生成准确回执。
3. M2：四机制齐全，错误重试、恢复、去重均通过。
4. M3：部署公开演示，完成至少一轮自助试用，再补账单与视觉。
5. M4：冻结功能，执行发布验收与提交链接检查。冻结后修复阻断问题，每次更新后重测受影响路径。

如时间紧张，依次取消 P2、复杂动画、账单导出；不能删到只剩演示截图，不能牺牲成功路径、结果准确或链接可访问性。

## 11. 视觉与文案方向

可信、克制的校务系统：教务蓝、白色内容区、清楚的状态标签、适度公文式排版。视觉精度服务于“这套荒谬制度真的存在”的可信感，不仿冒具体学校。

系统语气始终礼貌，不嘲笑用户、不直接承认恶意、不通过脏话制造笑点。逐步升级从“为你优化”到“为你保留”再到“尊重你的不完整方案”。按钮必须能辨认实际行为，不通过双重否定让用户提交相反结果。

每个办理步骤回答三个问题：为什么现在不能继续、还要做什么、已完成哪些。所有有意的阻挠都必须有产品理由和稳定出口。

## 12. 三分钟演示与答辩

| 时间预算 | 操作 | 评委应看到的证据 |
| --- | --- | --- |
| 0—20 秒 | 说明唯一入口与目标，搜索机器学习 | 目标明确且必须使用本系统 |
| 20—40 秒 | 查看第四位目标和排序说明 | 兴趣仅占 10%，机构目标占主导 |
| 40—90 秒 | 完整办理一次拒绝，答对测验 | 想不上课却要先通过课程考试 |
| 90—120 秒 | 加入目标，看到拒绝课回填并移除 | 拒绝被记录，却被权益保障绕过 |
| 120—150 秒 | 查看 78%，坚持提交并核对 | 合规与系统偏好是两回事 |
| 150—180 秒 | 查看回执及账单 | 真实完成任务，并能解释全部机制 |

关键讲述：“我们把拒绝做得比接受更费力，把学校的需求叫作你的适配度。程序每一步都正确执行，用户却不断为自己的决定付出成本。”

演示失误时可重试当前题、恢复页面或从已保存步骤继续；不临时改数据伪装成功。演示时间是排练目标，实际是否达到必须计时验证。

## 14. 依赖、风险与开放问题

| 风险 | 处理决定 |
| --- | --- |
| 评委认为只是普通难用的教务系统 | 四处机制对应不同机构目标；成功账单直接揭示设计逻辑 |
| 重复阅读和考试耗尽演示时间 | 只保留一门完整拒绝，三分钟排练；不增加真实等待 |
| 用户误以为 78% 无法提交 | 同屏明确“已满足提交条件”，始终提供可读出口 |
| 自动加课被认为是程序 Bug | 明示保障标签、加入反馈和保留的拒绝记录；提供确定移除路径 |
| 演示部署、登录或接口失效 | 核心不依赖登录及外部服务，提前公开部署并匿名实测 |
| 最后时刻修改导致已测链接失效 | 冻结后只修复关键问题，发布后按精确 URL 重测 |

开发启动前需落实但不阻塞 PRD 的问题：比赛确切截止日期和时间、正式演示时长、是否还有评分细则、现有部署账号与负责人。获得新信息后调整排期与演示脚本，不假定已授权任何付费服务。

若后续做产品或技术决策，另记录其依据；本 PRD 不预先填充技术架构，也不把未执行的验收标记为通过。

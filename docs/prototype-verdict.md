# 状态原型结论

问题：学生完成知情拒绝后，能否保留拒绝记录，同时经历一次保障课回填，再确定地移除它并提交准确、不可变的单课回执？

原型分支：[prototype/consent-state-model](https://github.com/BRMRs/course-choice-informed-consent/tree/prototype/consent-state-model)

原型提交：`b0a378c`。文件 `prototype-consent-state.html` 为单文件、内存状态的可丢弃探索工具，具备自由操作与成功/非法/重复三个引导流程。该文件不进入正式主分支。

结论：模型成立。拒绝记录和保障课生命周期必须独立保存；拒绝不能被回填覆盖；保障课必须记录“曾加入”和“已移除”以防止回填；核对后才能提交，并保存课程快照。

浏览器实际操作验证了：阅读 → 理由 → 系统回应 → 正确答题 → 确认拒绝 → 加入目标及保障课 → 真实两秒长按移除 → 重复加入不回填 → 核对 → 提交 → 重复提交回执不变。

正式 `state.mjs` 吸收这些业务不变量，并增加版本化状态恢复、真实提交时间由调用方注入、输入校验和有意义的业务测试。正式页面在 UI 层管理长按连续性、可见时长与本地保存。
